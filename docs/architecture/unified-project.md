# 统一项目架构

本文描述 OpenDirector 的目标业务架构和公共语义，不记录实现进度。长期原则见 [开发指导](../../AGENTS.md)，交付依赖见 [发展路线](../development/roadmap.md)。

## 目标与范围

用户与 Agent 在相同业务条件和授权范围内具备等价的创作能力，覆盖素材导入、内容生成、高级编辑、候选采用、时间线编排和视频导出。双方共同操作同一工程，可以相互接续编辑。

画布、时间线和面板是用户交互方式，业务能力独立于界面存在。Agent 按创作目标安排、执行和调整多步操作，通过减少重复操作与人工跟进提高视频创作效率；效率以满足同等创作要求的端到端任务衡量。

用户也通过右侧 AI 助手聊天框与 Agent 交互，提出目标、引用素材、委托任务并反馈或调整要求。Agent 通过共用服务执行操作并反馈进度和结果，工程变化同步呈现于画布；用户的直接修改进入同一工程，后续对话可接续处理。会话和消息引用保存必要上下文，不另存一份创作业务图。

统一的是业务能力、状态与规则。内置 Agent 可以直接调用应用服务，HTTP 和工具协议是不同适配入口；不要求 Agent 模拟鼠标，也不要求每个按钮对应一个工具。

画布创作与时间线编辑属于产品范围。完整剧作、制作台、全剧交付体系或新的模型协议需要单独需求，不由统一项目架构自动引入。

## 执行分层

```text
UI / HTTP / Agent 工具 / 后台编排
                 ↓
       类型化命令、查询与应用服务
                 ↓
       领域规则、对象版本、工程存储
                 ↓
      后台任务与模型 / 媒体适配器
                 ↓
       结果登记、回执、持久化变更
                 ↓
        工程查询与 UI / Agent 更新
```

入口层转换参数和展示结果；应用层协调事务和执行；领域层约束业务对象；存储与适配器处理文件、模型和媒体。共用能力不依赖某个组件、窗口或面板存活。

依赖只指向内侧。`domain` 不依赖应用、端口或基础设施。`ports` 定义应用服务调用的抽象（协议、提交文件契约和命令分发接口），可以依赖 `domain`，不依赖 `application` 或 `infrastructure`。`application` 依赖 `domain` 与 `ports`，不导入具体基础设施。`infrastructure` 实现这些抽象，可以依赖 `domain` 与 `ports`，不导入应用服务。`wiring` 是组合根：进程入口在执行命令前把基础设施实现注册到端口，并把命令分发交给应用层。

命令类型到应用服务的路由属于应用层。工程存储只提交已经决定的变更，不反向导入应用服务。

### Agent runtime 与业务执行

Agent runtime 复用 harness 的执行循环、原生工具、Skill 加载和上下文管理。OpenDirector 提供工程上下文、会话与业务工具；适配层负责进程和事件转换，业务服务负责校验与提交。各 runtime 操作同一工程，遵守本文件的命令、素材和执行约定。

Skill 提供规划方法与领域知识，由 harness 按需加载；技能内容不改变用户授权和业务规则。原生工具处理文件，业务命令登记产物及来源。源素材保持只读，每轮执行使用独立可写目录，运行文件只有登记后才成为工程素材。

执行预算由 harness 管理，工具入口负责调用校验、幂等重放和关闭协调。会话关联运行身份、轨迹和业务回执；停止回复需保留已完成内容并协调已接受操作收尾，不自动撤销工程变更或取消远端任务。

模型与认证来源、技能发现及运行生命周期见 [Agent 运行机制](agent-runtime.md)，需求与验收见 [Agent 协作开发文档](../development/agent-collaboration.md)。

## 业务对象

| 对象           | 权威内容                                 | 关键边界                                         |
| -------------- | ---------------------------------------- | ------------------------------------------------ |
| Project        | 工程身份和对象范围                       | 显示名称、目录名和稳定 ID 分别处理               |
| Asset          | 文件、指纹、媒体事实、实际来源           | 内容身份稳定，替换内容形成新素材版本             |
| GenerationSpec | 提示词、模型、参数和生成意图             | 不承载画布位置或临时选择                         |
| Reference      | 来源、目标配置、用途、顺序、版本策略     | 是真实业务关系，画布边由其投影                   |
| CanvasItem     | 业务绑定、展示、布局、层级和锁定         | 可隐藏，不能成为文件和输入的唯一容器             |
| 编辑文档       | 主体、图层、媒体编辑、时间线等结构       | 可保存、重开和继续编辑，引用稳定素材             |
| 执行任务       | 固定输入、实际模型、远端身份、状态与结果 | 生成任务和工具任务可分类型，但共享依赖与通知机制 |
| 结果与采用关系 | 候选、版本家族和当前采用                 | 任务成功与改变当前采用分别记录                   |
| 会话与运行记录 | 草稿、消息、引用快照和操作关联           | 对话不能成为另一份工程业务图                     |
| ViewState      | 选择、视口、播放头等界面状态             | 与业务保存分开，后台操作不抢走焦点               |

前端可组合这些对象形成便于渲染的视图模型；组合视图不能作为另一份可独立修改的权威工程。

## 三种不同的关系

- **创作参考**表达下次生成希望使用什么，可以跟随逻辑来源当前版本或固定指定素材。
- **实际来源**记录某次执行真正使用的素材版本、模型和参数，不随新编辑变化。
- **当前采用**决定界面或时间线使用哪个结果，以及使用的片段范围。

生成参考连线不表示自动执行依赖。时间线中的片段顺序、起止点、速度和声音编排也不由参考连线推断。Agent 通过明确操作安排任务、观察结果，再决定下一步。

正文引用通过稳定关系身份关联参考；名称和内容指纹不能代替逻辑来源身份。相同内容的独立来源分别保留，重复提及和实际媒体去重按各自语义处理。

正文引用与画布连线表达同一组参考关系，但职责不同：连线决定生成使用哪些来源，参考条带负责展示和断开连线；正文引用只会在插入时建立关系，删掉引用文字不会断开连线或移除来源，断开连线时同时清理正文中的对应提及。

## 命令与执行约定

- 修改携带稳定操作 ID、项目范围、类型化参数和必要的对象版本。依赖影响预览的操作同时校验预览依据。
- 相同 ID 与输入返回原回执；相同 ID 不同输入拒绝。响应丢失后先核对原操作，不能自动创建新的付费尝试。
- 回执区分应用成功、接受后台任务、无变化和拒绝，关联修改对象、版本、任务及问题。拒绝不能宣称创建了任务或修改了对象。
- 提交任务前解析真实参考，固定实际素材、输入、模型与执行参数。恢复原任务继续原执行依据，新输入形成新的尝试。
- 取消请求不等于远端已经取消；未知提交不能自动重发。项目撤销不能消除远端调用或费用事实。
- 组合操作共享基础规则；正式发布编辑文档、来源关系和展示绑定时明确原子边界。准备成功但未发布的素材保留可查询、可解释状态。

## 素材与编辑约定

所有上传、粘贴、资产选择、跨项目复制和编辑输出共用素材登记与校验基础，并明确操作意图。向已有节点替换本体时保护节点类型；添加参考不替换目标本体；主体和时间线遵守各自槽位规则。

服务端校验真实类型、实际字节、模型限制、聚合预算、文件可用性、来源身份、对象版本与锁定。UI 预检提供及时反馈，工具调用遵守相同限制。

### 浏览器里保留的即时校验

共享限额和菜单推导只有一份来源：`opendirector.domain.rule_facts`。`scripts/generate_contracts.py` 把它写成 `src/contracts/ruleFacts.generated.ts`。浏览器导入该文件，用来决定画幅、分辨率、有效视频模式、参考字节、音乐时长、歌词长度、提示词长度、参考数量和首尾帧图片上限。这些数值不再在前端另写一份。

下列检查留在浏览器，因为它们只服务即时反馈，或依赖尚未提交的界面状态。正式提交仍由领域规则拒绝：

- 空提示词、空白文本、未选择模型、本地文件尚未就绪。这是空态提示，不另设限额。
- 画布图遍历：主体如何展开、连线是否仍指向当前节点、首尾帧槽位属于哪条边。推导函数只接收已经算好的事实，例如“当前是否连着图片参考”。
- 发给语音服务的音色标识使用 `serviceVoicePattern`（ASCII）。工程里可以保存 Unicode 显示名；持久化模式是 `storedVoicePattern`。不要把两条模式合成一条。
- 拒绝原因的中英文文案。比较用的数字来自规则事实，文案只负责把同一个数字说出来。
- 拖动、选区、视口和未提交草稿。

`validate_generation` 仍是提交时的过程校验。`backendBlocker` 用同一份事实做提交前提示，分支本身还没有收进生成契约。参考是否真正送出由 `reference_policy` 决定；浏览器的 `backendReferences` 只根据已发布的 `inputRules` 预测可用参考。

编辑器保存结构化文档，输出保留来源素材和文档版本。仅保存最终像素不足以证明编辑器可重开；仅保存浏览器临时 URL 也不足以持久化素材。

隐藏展示对象保留逻辑来源和历史。删除素材前检查参考、编辑文档、生成任务、工具任务、结果、历史与来源依赖；依赖无法确认时不能报告素材未使用。

## 存储、通知和交互

工程文件是权威数据。对象、文件、回执和变更记录通过明确的提交顺序与恢复机制协调；SQLite 可用于租约等运行协调。凭证不进入普通工程、公开回执或模型快照。

UI、Agent 和后台完成写入共享可恢复变更通道。通知提示对象发生变化，查询返回权威状态；处理断线、重复和乱序，不能通过整页重载掩盖同步问题。

浏览器保存草稿、交互状态和可重建缓存。拖动中不逐指针写盘；按受影响对象更新，避免反复读取大媒体或全历史。冲突保留输入，视图保存失败与业务提交结果分别反馈。

跨项目浏览使用只读查询。正式复制时将所需文件登记到目标工程；新格式交换明确包含哪些素材、配置和历史，不把画布视图副本称为完整工程备份。

### 交互设计约定

交互设计以尽可能简化用户操作为原则。在保留创作能力和用户控制权的前提下，减少不必要的点击、重复输入、面板切换和人工等待，让用户完成当前操作后可以自然进入下一步。涉及创作取舍和授权的决定由用户掌握。

#### 参数发现与错误反馈

命令帮助从共用业务契约派生，所有命令及其联合类型使用一致的渐进展开规则。联合分支返回用途、选择条件、必填字段及可继续查询的字段路径，调用者可以据此选择分支并构造完整参数。素材引用、模型配置和业务对象的身份说明应给出其查询或回执来源。

参数校验失败的回执应包含具体原因、出错字段及对应命令帮助路径。联合类型错误同时返回允许的分支和分支帮助入口；嵌套对象错误指向可展开的字段或最近有效父级。CLI 回执同时给出可直接执行的子命令帮助入口及对应字段；结构化字段路径必须能在同一命令帮助中定位，不能要求调用者从内部校验路径猜测转换规则。错误反馈与命令帮助复用业务契约，适用于 UI、CLI 和 Agent 入口。

画布元素的位置由用户或 Agent 根据当前工程状态安排。创建与修改回执应提供对应提交版本的元素身份、位置、尺寸、父级和版本信息，并明确位置所在坐标系，使 Agent 可以观察结果、判断遮挡并继续调整布局。补充信息读取失败时，应分别表达业务提交状态和读取错误，避免将已经提交的修改描述为执行失败。

#### 选择与输入焦点

新建或选中节点时，键盘焦点留在画布，复制、粘贴和删除快捷键作用于画布。用户点击提示词输入框、通过键盘导航进入或主动展开生成面板时，输入框接收焦点。空输入框的光标位于正文起点，placeholder 不参与正文排版。

参数调整、保存回执、后台及 Agent 更新保留用户正在操作的控件焦点。输入框持有焦点时，方向键、删除与选择快捷键作用于文本。

同步新增的画布节点进入可见区域时，视口可居中展示新节点，并避让侧栏与 AI 对话面板；批量新增按整体范围展示。跟随不修改节点位置、选择或输入焦点。用户拖动、缩放、多选或编辑时不自动移动视口，结束操作后不补做已跳过的跟随。已有节点的状态更新不触发重新定位。

焦点属于 ViewState，不改变业务对象版本、生成意图或采用关系。

## 模型与渲染边界

模型接入使用能力契约和协议适配器，参数依次贯穿表单、生成配置、实际执行和历史依据。无法支持的参数明确限制，不静默忽略或降级。

浏览器与后台的执行职责必须明确。Agent 可以修改时间线，不代表后台已经能够导出视频；只有存在可调用渲染服务并验证真实输出，才可声称支持关闭浏览器后的自主导出。浏览器合成也可以作为明确需要客户端参与的能力保留。
